## 追加结论（10:22）：**不需要刷 system**

用户问「不用刷 system 吗」——这是对的追问，原回答确实漏了论证。补做完整核查：

### OHOS GL 栈是两层
`/system/lib64/platformsdk/libEGL.so` 是 **wrapper**（NEEDED samgr/ipc/configpolicy，
内含字符串 `libEGL_impl.so`/`libGLESv2_impl.so`/...），靠 dlopen 加载实现层。
Mesa 25 提供的就是 `_impl` 层，**wrapper 不用换**。

### 符号契约零回退（关键数据）
- mesa22 有、Mesa25 没有的 `egl*` 符号：**0 个**
- Mesa25 新增 `egl*` 符号：**461 个**
- wrapper 引用但两者都缺的 19 个（EGLStream + Android 私有扩展），
  **逐个核对在旧 mesa22 里同样都不存在** → wrapper 本来就"有则用无则跳过"
- 方法坑：`readelf` 只看 `GLOBAL DEFAULT` 会把大量 LOCAL 实现符号漏掉，
  必须按 `$4=="FUNC"` 取全符号表，否则误判成"缺几十个符号"

### 依赖完整性
Mesa25 的 8 个外部依赖在现有 system.img **8/8 命中**：
libdrm(chipset-sdk) / libhilog(chipset-sdk) / libhitrace_meter(chipset-sdk-sp) /
libbegetutil.z(chipset-sdk-sp) / libsurface.z(chipset-sdk-sp) / libc++(chipset-sdk-sp) /
libc(/lib64) / libqos.z(/lib64)

### libdrm 没有 msm 后端 —— 不是问题
system 的 libdrm.so 里 **0 个** `msm_*` 符号，看着像坑。
但 `libgallium-25.0.1.so` 对 libdrm 的 UND 只有通用原语
（drmIoctl / drmGetDevice / drmPrime* / drmSyncobj* / drmCommandWrite 等 15 个），
**`msm_*` 引用数 = 0**。freedreno 走 mainline DRM 直接对 /dev/dri/card0 发 ioctl。
这 15 个符号在 system libdrm 里 **15/15 导出**。
→ 这是「mainline DRM 无 KGSL」路线的实打实好处：不必为 libdrm 刷 system。

### libqos ABI 未断
vendor 的 libqos.so 只从 libqos.z.so 导入 3 个符号
（GetThreadQos / SetThreadQos / ResetThreadQos），system 现有 libqos.z.so 全有。

### Vulkan loader
system 的 libvulkan.so 是标准 Khronos loader，走标准 ICD 契约
（vk_icdGetInstanceProcAddr / vk_icdNegotiateLoaderICDInterfaceVersion），向后兼容。

### 何时才需要刷 system（判据）
改 frameworks/graphic 或 graphic_2d；换 system 侧 libvulkan/EGL wrapper；
改用需要 libdrm msm 后端的方案（如回 KGSL）；App 依赖的 SDK 接口版本变化。

## 开机失败诊断：libffrt.so 装错目录（10:41）

用户刷了 system/vendor/userdata 后不开机，12 秒后重启循环。给了 log1.txt。

### 现象
4 次启动、3 次重启。第 2、3 段有 `[init_reboot.c:24]ExecReboot panic`，
第 1、4 段只有内核 `reboot: Restarting system`。

### 根因
- 崩溃进程：`appspawn`，`exit with signal : 11`（SIGSEGV）
- 缺失依赖：`libffrt.so`
- 实际位置：`/system/lib64/ndk/libffrt.so`
- `/system/lib64/ndk` **不在** musl 搜索路径
- `appspawn.cfg` 有 `"critical": [1, 4, 240]` → 240s 内崩 4 次 → `ExecReboot("panic")`

**appspawn 启动后一行自身日志都没有就 SIGSEGV**，这是动态链接阶段失败的典型特征。
与 Mesa 无关（appspawn 的 NEEDED 里没有任何 GL 库）。

### 为什么装错（重要坑）
`foundation/resourceschedule/ffrt/BUILD.gn` 原为：
```gn
innerapi_tags = [ "chipsetsdk_sp", "ndk", "sasdk" ]
```
`build/templates/cxx/cxx.gni:741-747`：
```gn
if (is_ndk) { auto_relative_install_dir = ndk_dir }   # 最后覆盖，丢弃前面所有 tag
```
只要列表里有 `ndk`，前面的 `chipsetsdk_sp` 目录被完全丢弃。
`build/ohos/packages/rules/categorized_libraries_utils.py:45` 里更直接：`if is_ndk: return "ndk"`。

### 关键校正：搜索路径到底有哪些
`third_party/musl/scripts/paths.json` 里 **没有 `ndk`，也没有 `chipset-sdk-sp`**！
只有 `chipset-sdk`（无 -sp）、`chipset-pub-sdk`、`platformsdk`、`priv-platformsdk`、
`priv-module`、`module*`、`/lib64`、`/lib`。
→ 我一开始想改成 `chipsetsdk_sp` 是错的，它会落到 `chipset-sdk-sp/`，依然搜不到。
最终改成 `innerapi_tags = [ "chipsetsdk" ]`（落 `chipset-sdk/`，在路径内）。

### debugfs 操作 ext4 的坑
`/lib64` 是**符号链接** → `/system/lib64`。
用 `debugfs -w -R "write x /lib64/libffrt.so"` 会失败，
并在 inode 表留下 `Type: bad type / Links: 0` 的垃圾 inode。
**必须用真实路径 `/system/lib64/...`。**

### 影响范围
`/system/bin` 337 个可执行文件中 **184 个**依赖 `libffrt.so`：
appspawn/cjappspawn/hilogd/hiview/hybridspawn/nativespawn/nwebspawn/samgr/usage_report
+ ~120 个 system/lib64/*.z.so + ~60 个 platformsdk/*
→ 不是 appspawn 个例，samgr/render_service/hilogd 都会全挂。

### 修复
镜像（已做）：把 `/system/lib64/ndk/libffrt.so` 复制到 `/system/lib64/libffrt.so`，chmod 0644。
源码（已改）：`innerapi_tags = [ "chipsetsdk" ]`。

- `e2fsck -fn` 干净
- 重扫 337 个 bin：只剩 `hcodec_demo`（测试 demo）缺 `libnative_media_core.so`
